# Statistical and decision CPU diagnostic map

Implementation: `scripts/check_statistics.py`.

The child author read the actual assigned pinned Markdown snapshots, including **R05 v4** and **R03 v3**, rather than inferring their claims from titles or earlier versions. This contribution writes code and this mapping only. It does not execute numerical code, install dependencies, launch the runner, publish, or change project/candidate state. The root executes the suite serially and owns execution results and interpretation.

Every scientific check is a **constructed deterministic numerical diagnostic**. Passing supports a specified small-case identity, conditional bound, optimization, or expected failure boundary. It is not a mathematical proof, a public/native benchmark result, deployment calibration, semantic-validity evidence, an empirical method improvement, or a reason to change candidate/admission/selection counts. An expected counterexample reproduced correctly is a passed **boundary** check.

The CLI is:

```bash
python scripts/check_statistics.py --output results/statistics-seed0.json --seed 0
```

The output schema is `{suite, seed, checks, elapsed_seconds}`. Each check includes `id`, `lineage`, `scope`, `status`, `metrics`, `source_refs`, and `interpretation`. `source_refs` include the exact source path and its manifest SHA256, repository commit, and the SHA256 of the current source manifest. The initial integrity check rehashes the assigned sources. A changed assigned snapshot makes its numerical checks fail instead of silently validating different source bytes. NumPy/SciPy dependency absence yields `inconclusive`; a diagnostic exception or failed comparison yields `failed`. JSON serialization rejects nonfinite values.

## Numerical and resource contract

- All arithmetic fixtures use NumPy FP64, apart from exact integer modular arithmetic and combinatorial graph/encoder enumeration. Seeded random numbers generate bounded small fixtures; there is no Monte Carlo hypothesis test, significance claim, sample-based calibration, or noisy benchmark estimate.
- Default comparison tolerances are absolute `2e-10` and relative `2e-9` for small deterministic identities. Cancellation of near-zero PSD eigenvalues, transport balances, and polynomial evaluations is covered by the absolute tolerance. Convex-optimizer versus formula comparisons allow `2e-6`, reflecting numerical optimization termination at kinks and constraints rather than scientific effect sizes. LP comparisons and feasibility boundaries use small, well-scaled fixtures; quadrature accumulates and checks its own error estimate below `1e-9`.
- The largest constructed graph has nine vertices; the largest posterior-law LP has at most 42 variables; the complete composed scalar loss has degree 54. There are no dense benchmark datasets, learned-model activations, downloads, GPU tensors, or public benchmark scorers. Diagnostic arrays fit easily under a 256 MiB data-allocation cap. Imported library/process memory is separate from this data bound.
- The root's initial seed-0 dispatch reported all 24 checks passing in 1.58 seconds (resource wall time 1.89 seconds, peak approximately 82 MiB). That exact dispatched script is preserved at `checkpoints/check_statistics.pre-highs-thread-v1.py`. These are root-reported results; the child did not execute the suite.
- The subsequent v2 script adds explicit HiGHS `threads=1` and `parallel=False` options to every LP call, separately from the root's BLAS/OpenMP thread environment. Static inspection of the installed SciPy `_linprog_highs.py` confirms unknown solver-specific options are passed verbatim; `_highspy/_highs_wrapper.py` converts the Boolean `parallel` option to native `"off"`. SciPy may emit an `OptimizeWarning` saying these options are forwarded, which does not itself mean rejection. The root owns fresh-byte runtime/thread verification; the v1 timing does not prove one total CPU thread.
- Post-review development also replaces R17's initially literal zero-residual metric labels with computed/validated zero-score branches and adds the orthogonal-protection case. This diagnostic addition is identified explicitly in its metrics. Initial v1 results are preserved and do not imply execution of the added v2 cases; fresh dispatches are required.
- Suite JSON status is a diagnostic status only. Failed source integrity, optimizer failure, arithmetic mismatch, or exceptions must be reviewed individually. A passing expected-boundary check preserves its original failure limitation and is never counted as a newly successful method.

## Coverage gaps and warnings

This suite does not evaluate public/native endpoint accuracy, randomized deployment action data, calibration coverage, free-running neural losses, semantic fact validity, bit-exact floating-point Delta releases, or matched-total-cost superiority. It does not acquire external probes; the channels are explicitly supplied constructed experiments. It does not estimate a pointwise future-Gram certificate, a uniform global derivative envelope, a complete closed-loop kernel, or the observational TV of real provenance worlds.

Within assigned lineages, untested extensions include approximate sequential-DR nuisance/ratio remainder theory; general continuous/Polish-space Wasserstein behavior and calibration coverage; countably infinite conditional contexts and measurable selection; nonrectangular action-channel ambiguity; general rich provenance experiments; noisy/interpolated high-order response recovery; randomized spectral-compressor coverage; finite extension fields/nonprime `q`, hidden/state-dependent lawful branch graphs, repeated destructive writes, or noisy/approximate syndrome coding; general indirect Gaussian observation models, optimal vector/block/nonanticipative code construction, and causal quantizer design; general correlated lossy-cache regions and adaptive demand adversaries; continuous probe channels, correlated/copied-source misspecification, and randomized probe-selection minimax games.

Other source families—including the separate `STEP2_QUERY_SHIFT_SUCCESSIVE_REFINEMENT_2026-10-12.md`, martingale-release, randomized-mask variance/survival, noisy-key identification, and random-truncation covariance—are outside this delegation unless another suite covers them. The mapping does not imply that the entire 70-source packet was numerically verified by `check_statistics.py`.

Theoretical claims that require all states/actions/branches are checked on the **entire declared tiny diagnostic domain** where feasible. Continuous/global claims are tested on exactly solved small conditional subfamilies and retain their stated assumptions. All lineages remain scoped theorem/control objects with empirical effect unknown until evidence beyond these constructed diagnostics exists.
